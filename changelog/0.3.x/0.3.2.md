# 0.3.2 — 2026-11-25

## Added

- **`publication_sections`** on `artic_get_artworks` records and `artic://artworks/{id}`: links (`id`, `title`, `publication_title`, `web_url`) to the museum's online scholarly catalogue entries on the work. A response with any carries **`publication_license_text`** (the museum's statement for those sections, verbatim: noncommercial educational and personal use) and **`publication_citation`**; one without carries neither. Links only, no section text (#35).
- **Text documents** a record links to (gallery labels, catalogue scans, teacher manuals, poems) join `related_media` after the sounds, with `type: "text"`. `include_related_media` gates all three kinds on the tool; the resource always loads them. 0.3.1 returned sounds only (#35).
- **`provenance`** on `artic_search_artworks`: `recorded` keeps works whose record carries provenance text, `unrecorded` those whose record carries none. Combines with every other filter, with `facets`, and with `limit: 0`. It reads whether text is present, not whether the provenance is complete (#37).

## Changed

- **`artic_get_artworks`** with `include_related_media` on (the default) sends one linked search per kind its records link to, at the same time: up to three where 0.3.1 sent one. Each kind loads up to 100 items. A linked search waits at most 12 seconds for a request slot (0.3.1 waited out the 20-second deadline), so under load links are dropped before records. The degraded and capped notices name the kind: "The linked sound recordings could not be loaded; …" where 0.3.1 said "Related media could not be loaded; …" (#35).
- **`page_beyond_window`** recovery hint on the four paged searches ends by telling the caller to start again at page 1.
- **`@cyanheads/mcp-ts-core` ^0.13.18 → ^0.13.22**: `initialize` advertises the server description from `package.json` (cyanheads/mcp-ts-core#683); an `MCP_PUBLIC_URL` or `MCP_HTTP_ENDPOINT_PATH` value with no single reading now fails startup (cyanheads/mcp-ts-core#831, cyanheads/mcp-ts-core#830). All three shipped in 0.13.21.
- **Bun** requirement `>=1.4.0` → `>=1.4.4` in `engines` and the README.
- **Skill, instructions, and docs**: the `art-institute-chicago-guide` skill is 1.2 (paging past match 1,000, the `provenance` filter, publication sections, and licensing rows for text documents and publication sections). The server `instructions` and the Codex plugin description name publication sections in their licensing sentence. README and design-doc corrections cover paging, licensing, and the share of works with no provenance text (97,960 of 133,375, 2026-11-24).

## Fixed

- **Paging** on `artic_search_artworks`, `artic_search_artists`, `artic_search_exhibitions`, and `artic_search_audio_guide`: the page that crosses match 1,000 returns the matches up to it (`limit: 12`, `page: 84` returns matches 997–1,000) instead of failing `page_beyond_window`, and the notice says the page was shortened when more matches exist past the window. A page that starts past match 1,000 still fails `page_beyond_window`, and its message now names the match the page starts at (#33).
- **Number and boolean inputs** on all six tools read strings that spell one (`"5"`, `"-500"`, `"true"`), which 0.3.1 rejected with `invalid_arguments`. The accepted forms are exact: `"05"`, `"1e3"`, and `"yes"` still fail. The advertised schemas don't change (#36).
- **`htmlToText`**: site-relative links in museum HTML (agent biographies have them) print as `(https://www.artic.edu/…)` instead of losing their destination (#38).
